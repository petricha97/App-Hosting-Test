## Consolidated defect list (all severities, across all 4 phases)

### Blocker

1. **QA-1** (Phase 1) — Signup and any session older than ~1 hour trap the user in a genuine, live-reproduced infinite `/login` ↔ `/dashboard` redirect loop. The "already logged in" auto-redirect/"Go now" path in `login-form.tsx` never calls `syncSessionCookie()`. Routing: fullstack-developer + security-agent.
2. **QA-1b** (Phase 1) — Root cause of QA-1's higher-frequency trigger: the server session cookie stores a raw ~1-hour Firebase ID token with a 24h cookie `maxAge` and no refresh mechanism anywhere in the codebase (`onIdTokenChanged` has zero usages). Any user with a tab open past ~1 hour hits the same trap. Routing: fullstack-developer + security-agent.
3. **QA-9** (Phase 4) — Every Firestore aggregate query added by M7-T1/M8-T2/M8-T3 that sums a nested money field (`amounts.totalMinor`) or combines `count()`/`sum()` with a range filter throws `FAILED_PRECONDITION` against **real production Firestore** — confirmed via direct Admin SDK repro, not inferred. Breaks the Finance card (M7-T1), the workspace Revenue stat (M8-T2), and both the event overview's Revenue and Abandoned stats (M8-T3) — unconditionally, on every page load, for every org with any real order or abandoned draft. Every prior sign-off for these 3 tickets was unit-test-only (`fake-admin-db`), which cannot enforce Firestore's real composite-index requirements — the affected DAL files' own code comments falsely claim this was "confirmed empirically against a live Firestore emulator." Fix is 3–4 composite indexes in `firestore.indexes.json`, no app code changes. Routing: backend-agent.

### Major

4. **QA-2** (Phase 1, confirmed live) — Fee/Tax dialog "Base price"/"Rate" inputs aren't associated with their labels (`FormControl`'s id lands on a wrapper `<div>`, not the real `<input>`). Routing: ui-ux-designer + fullstack-developer.
5. **QA-3** (Phase 1, confirmed live) — Promotion Template "Discount Type" is an unconstrained free-text input; only exact lowercase `"percentage"`/`"fixed"` render correctly downstream. Routing: ui-ux-designer + fullstack-developer.
6. **QA-6** (Phase 1) — Ticket Types Price column compares `basePriceMinor` across different currencies as if they were the same unit, so a GBP fee can display as "the price" over a numerically-larger USD fee with no currency-mismatch framing. Routing: fullstack-developer.
7. **QA-8** (Phase 2) — Registration Path create/edit dialog silently wipes in-progress Name/Code/Audience input when a background `router.refresh()` (triggered by an unrelated sibling mutation) resolves while the dialog is open — a real silent-data-loss risk on an ordinary "create several paths back-to-back" workflow. Reproduced twice independently. Routing: fullstack-developer.

### Minor / Minor-to-Major

8. **QA-4** (Phase 1, confirmed live) — Promotion Template's "Enable promo code" switch has no accessible label. Routing: ui-ux-designer + fullstack-developer.
9. **QA-7** (Phase 1) — 18 API routes crash with a bare, opaque 500 instead of a clean 400 on empty/malformed JSON bodies (missing try/catch around `request.json()`), reproduced live via curl. Not exploitable, but a real robustness/observability gap. Routing: backend-agent + fullstack-developer.

### Low / Informational

10. Bonus finding (Phase 1, code-read only) — `decodeUser()` serializes missing token fields as literal strings `"No name"`/`"No picture"`/etc. instead of `null`. Routing: fullstack-developer.

### Tooling limitations (not product defects, disclosed for transparency)

- M4-T1/M6-T4 (Phases 2 & 3): Puck's pointer-based `@dnd-kit` drag-and-drop could not be reliably automated in Playwright across multiple attempts in this environment. Data-binding/render-pipeline correctness for the affected blocks was independently verified via source review and real authenticated API calls instead. Recommend a follow-up manual or component-level test before considering M4-T1/M6-T4 fully proven end-to-end via literal mouse-drag.

## What this effort validated that prior (unit-test-only) sign-offs could not

- The entire real public registration flow, real payment/discount/tax math, real QR mint-and-scan cycle, real email triggers, and real IAM permission enforcement all genuinely work against production infrastructure, not just mocks.
- QA-9 is the headline result: three previously-"Done," unit-test-signed-off features are **completely non-functional in production** in a way no fake-Firestore-backed test could ever have caught. This directly validates the premise of running this regression against the real backend instead of trusting mocked sign-offs.

## Recommended next steps (for the human/owner, not auto-actioned)

1. Fix QA-9 first (Blocker, straightforward index-only fix, unblocks 3 shipped features).
2. Fix QA-1/QA-1b together (Blocker, same root cause, affects every real user's session longevity and every new signup).
3. Triage QA-8 and QA-6 (Major) next sprint.
4. Sweep QA-2/QA-3/QA-4/QA-7 as a batch cleanup (all Minor-to-Major, all independent, all already root-caused with a suggested fix).
5. Close the M4-T1/M6-T4 drag-and-drop verification gap with a manual pass or a component-level test.
6. All 27 new Playwright spec files under `e2e/` are real, re-runnable regression tests — wire `npm run test:e2e` into CI so this class of production-only bug (QA-9) gets caught automatically going forward, not just in one-off live sweeps.
