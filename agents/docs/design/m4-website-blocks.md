# M4 Design Spec — Website Blocks (M4-T1) + Per-Path Pages (M4-T2)

UX Designer, 2026-07-11. Sources: `prototype/prototype/event-page-builder.html`, BACKLOG M4, `src/features/event-pages/puck.tsx`, `event-page-editor-workspace.tsx`, `public-custom-event-page.tsx`, M3 public-registration components.
**Divergence risk:** `agents/docs/specs/m4-website-blocks.md` did not exist at design time — this spec is derived from prototype + backlog. If the research spec lands with different block props/data-binding, reconcile before dev (this file wins on visuals, the RL spec wins on data semantics).

## 0. Conventions (all three blocks)
- Blocks render on the **public page and in the Puck canvas**, which are light-only by design (existing blocks hard-code slate/orange). New blocks follow the same vocabulary: section shell `rounded-[2rem] border border-slate-200 bg-white px-6 py-8 sm:px-8`, headings `text-2xl font-semibold text-slate-950`, body `text-sm leading-7 text-slate-600`. Builder *chrome* (toolbar, banners, paths table) uses semantic tokens (`bg-card`, `border-border`, `text-muted-foreground`) like the M1–M3 workspaces.
- Live data is **injected at config creation**, extending the existing pattern (`assets`, `registrationRender`): `createEventPagePuckConfig({ assets, registrationRender, pricingTickets, countdown, registrationState })`. Server components load the data; no client fetch inside block renders. Editor receives the same live data via the workspace page's server loader.
- Money: always `formatFeePrice` from `src/features/pricing/utils` (renders `Comp` for 0); "From <min>" rule mirrors `src/features/public-registration/ticket-price.ts` (min shown only when per-registration-type prices differ).

## 1. TicketPricingTable block (new)
**Component:** `src/features/event-pages/blocks/ticket-pricing-table.tsx`, registered in `puck.tsx` as `TicketPricingTable`.
- **Props (Puck fields):** `heading` (text, default "Tickets & pricing"), `intro` (textarea, optional), `showCodes` (radio Yes/No, default Yes — hides the Code column), `currency` (select: "All currencies" + one option per currency present in fee data; default All. When filtered, only rows priced in that currency show).
- **Data shape (injected `pricingTickets`):** per ticket: name, code, availability (`open | closed | sold_out` — derived server-side from sales window + capacity), currency, exact `priceMinor` or per-reg-type price list (drives "From").
- **Public render ≥640px:** semantic `<table>` (`Table` primitives are dashboard-styled; use a plain table with the block vocabulary): columns Ticket (name `text-sm font-semibold text-slate-950`) / Code (`font-mono text-xs text-slate-500`, toggleable) / Availability (Badge: Open `bg-emerald-100 text-emerald-900`, Closed `bg-slate-100 text-slate-600`, Sold out `bg-amber-100 text-amber-900` — matches M3 step-2) / Price right-aligned `tabular-nums font-semibold` ("From $X" or exact). Row divider `border-slate-200`, header row `text-xs uppercase tracking-[0.16em] text-slate-500`.
- **Public render <640px:** stacked cards (`rounded-[1.5rem] border border-slate-200 bg-slate-50/80 p-4`) — name + code left, badge + price right; identical content, same look as the M3 ticket radio-cards minus the radio. Implement as two siblings with `hidden sm:block` / `sm:hidden` (the `display:none` variant leaves the a11y tree, so no SR duplication).
- **States:** *Empty (no tickets/fees):* heading + intro render, body replaced by dashed card "Tickets will be announced soon." — never a broken empty table. *Editor with no live data yet:* 3 sample rows with a `Badge variant="secondary"` "Sample data" pinned above the table; sample rows disappear the moment live data arrives. *Editor loading:* 3 skeleton rows (`Skeleton` h-5 w-full). *Post-publish drift:* public always re-reads live data at request time — no stale-copy state needed; note this in dev handoff for RL alignment.
- **A11y:** `<caption class="sr-only">{heading} — ticket prices</caption>`, `scope="col"` headers; badges carry text, never color-only.

## 2. Countdown block (new)
**Component:** `src/features/event-pages/blocks/countdown.tsx`, registered as `Countdown`.
- **Props:** `label` (text, default "Event starts in"), `targetMode` (radio: "Event start date" | "Custom date"), `customTarget` (custom field: `<Input type="datetime-local">`, only meaningful when custom), `completedMessage` (text, default "The event is underway."). Injected `countdown`: `{ eventStartIso, timezone }`.
- **Render:** centered row of 4 unit tiles (Days / Hrs / Min / Sec) per prototype canvas: value `text-3xl sm:text-4xl font-semibold tabular-nums text-slate-950`, unit `text-xs uppercase tracking-[0.16em] text-slate-500`, tiles `flex gap-6 sm:gap-10 justify-center`; below, one muted line with the absolute target ("September 15, 2026 · 9:00 AM ET").
- **Hydration/no-shift:** server renders the full tile structure with `--` placeholders; each value span reserves width (`inline-block min-w-[2ch] tabular-nums`, days `min-w-[3ch]`). A client `useEffect` starts a 1s interval and swaps real values in — no server/client mismatch, no layout shift. No `Date.now()` during render.
- **At zero / past target:** tiles are replaced by the `completedMessage` in the heading style; in the editor, if the resolved target is past, show the message plus an inline hint chip "Target date has passed" (editor only).
- **A11y (decision):** ticking tiles wrapper is `aria-hidden="true"`. A sibling `sr-only` paragraph states the static fact: "{label}: event starts {absolute date/time}" — no live region on the ticker (SR spam). On completion only, a `role="status"` node announces `completedMessage` once.

## 3. RegistrationEmbed (redesigned CTA card)
Keep the existing type name `RegistrationEmbed` and `title`/`body` props (saved pages must not break); add `buttonLabel` (text, default "Register now").
- **New render (both renderers in `puck.tsx`):** CTA card replacing the inline form: orange section shell (reuse the current `SharedRegistrationPlaceholder` frame: dashed orange border, `bg-orange-50/70`), eyebrow "Registration", `title` h3, `body`, then a pill button (`rounded-full bg-[#ff7a59] px-5 py-3 text-sm font-semibold text-white`, hover `bg-[#ff6a45]`, focus `focus-visible:ring-2 ring-orange-300 ring-offset-2`). Public renderer: `<Link href={/events/{eventId}/register{?path=…}}>`. Dashboard renderer: same visuals, button is a non-navigating preview with a caption "Links to the public registration flow".
- **Closed / no-active-paths state:** injected `registrationState: "open" | "closed"`. When closed (no active paths or event not accepting): button becomes a disabled-styled span (`bg-slate-200 text-slate-500`, `aria-disabled="true"`, not focusable) plus line "Registration is currently closed. Check back soon." Editor additionally shows an amber inline note "No active registration paths — activate one under Registration Paths" linking to the paths screen.

## 4. Builder integration
- **Palette grouping:** use Puck `categories`: "Content" (Hero, Highlights, Story, Schedule, Faq, CallToAction) and "Registration" (RegistrationEmbed, TicketPricingTable, Countdown) — mirrors the prototype's brand-highlighted cluster.
- **"New" badges:** prefer Puck `overrides.componentItem` to append `<Badge className="bg-violet-100 text-violet-900 rounded-full">New</Badge>` for `TicketPricingTable` and `Countdown`; if the installed Puck version lacks the override, fall back to label "Ticket & Pricing table — New". Drop behavior: default Puck drop; blocks get ids via existing `ensurePuckDataIds`.
- **Device preview:** configure Puck `viewports` `[{width:360,label:"Mobile"},{width:768,label:"Tablet"},{width:1280,label:"Desktop"}]` (canvas is an iframe, so the table's `sm:` collapse behaves truthfully at 360). Mirror in the "Public render preview" card: a 3-toggle segmented control (Buttons `variant="outline" size="sm"`, `aria-pressed`, icons Smartphone/Tablet/Monitor + sr-only labels) constraining the `Render` wrapper to `max-w-[360px] / [768px] / none` `mx-auto`. Verify at 360: pricing table = cards, countdown tiles wrap `gap-6`, CTA button full-width (`w-full sm:w-auto`).

## 5. M4-T2 — Per-path page switcher
- **Builder toolbar:** a `Select` beside the existing mode controls inside the "Custom page editor" CardHeader, labeled "Editing page" (visible `Label`, not placeholder-only): options "Default event page" + one per path ("2 — Delegates (invoice)" style, path name + payment hint). Switching pushes `?path=<pathId>` (router, shallow) and reloads that page document; unsaved-draft guard: confirm dialog "Discard unsaved changes to this page?" if local draft differs. localStorage cache key becomes `event-page-editor-cache:{eventId}:{pathId|default}`.
- **Inherit-fallback state:** when the selected path has no page document, editor shows an inline banner above the canvas (`rounded-2xl border border-border bg-muted/50 p-4`): text "This path currently inherits the default event page." + two actions: `Button` "Start from a copy of the default page" (primary) and "Start blank" (outline). Canvas below renders the default page read-only (dimmed, `pointer-events-none opacity-60`) until one is chosen. Publish/Save act on the per-path document only after that choice.
- **Paths admin entry point** (`registration-paths-workspace.tsx`): add a "Page" column between Currency and Active: `Badge variant="secondary"` "Default" or violet "Custom", followed by a link `Customize` (`Button variant="ghost" size="sm"` asChild → `/dashboard/events/{eventId}/page-builder?path={pathId}`, `aria-label="Customize page for {path.name}"`). Column hidden under `sm` via the table's existing `overflow-x-auto` (no special collapse).
- **Public routing note for dev:** register flow entry `?path=` selects the path page, else default — fallback must never 404.

## 6. Files, states summary, a11y
- New: `src/features/event-pages/blocks/ticket-pricing-table.tsx`, `blocks/countdown.tsx`, `blocks/registration-cta.tsx` (shared CTA card used by both renderers). Modified: `puck.tsx` (config options, categories, registration render swap), `components/event-page-editor-workspace.tsx` (path select, banner, viewports, preview toggles), `public-custom-event-page.tsx` (pass injected data + path resolution), `registration-paths-workspace.tsx` (Page column).
- Permission-denied/error on editor data loads: reuse the workspace's existing toast pattern (`toast.error` + retry via existing refresh affordances); blocks themselves never render error text publicly — they degrade to their empty states.
- Keyboard: palette and canvas keep Puck defaults; new interactive elements (device toggles, path select, banner buttons, CTA link) are native controls in DOM order; focus rings via `focus-visible:ring-2` in both themes.
