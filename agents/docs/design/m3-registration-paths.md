# Design Spec — M3 Registration Paths, Commerce Fields, Public Flow, Responses Workflow

Source: `agents/docs/specs/m3-registration-paths.md` (authoritative, ACs referenced as T1-AC-n), prototypes `event-registration-paths.html`, `event-form.html`, `responses.html`; patterns from M1 (`src/features/registration/`) and M2 (`src/features/pricing/`, design §5 states/a11y conventions apply verbatim unless overridden here).

New shared primitives (both from the already-installed unified `radix-ui` package, standard shadcn wrappers — no new deps): `src/components/ui/dropdown-menu.tsx`, `src/components/ui/tooltip.tsx`.

## 1. Registration Paths admin — `/dashboard/events/[eventId]/registration-paths`
Server page fetches paths + registration types (for audience names), renders `<RegistrationPathsWorkspace>`; `loading.tsx` = `EntityScreenSkeleton` plus one extra `Skeleton h-28 w-full rounded-2xl` above it (flow card). Nav item loses `comingSoon` in `src/features/event/event-nav.ts`.

- **Header** (M1 pattern): `h1 text-xl font-semibold tracking-tight` "Registration paths" + sub "The multi-step flow a registrant goes through. Different audiences / payment methods get different paths." CTA `Button` "+ Create path".
- **InfoNote** (always visible, incl. empty state): "A path is the flow a registrant walks through — create one per audience × payment method. The same audience paying by card and by invoice = two paths." Second sentence: "The path also pins the checkout currency."
- **Flow-diagram card** (`FlowDiagramCard`, hidden when zero paths): `rounded-2xl border-border bg-card p-5`. Title `text-sm font-semibold` "Path: {first active path name}"; sub `text-sm text-muted-foreground` "Each page is customizable in the Page Builder." (plain text in M3 — no link until M4-T2). Steps row: `flex flex-wrap items-center gap-2`; each step a chip `rounded-full border border-border bg-muted/50 px-3 py-1.5 text-xs font-medium text-foreground` reading `1 · Personal Information` … `5 · Confirmation + QR`; connector `ChevronRight h-3.5 w-3.5 text-muted-foreground` with `aria-hidden` between chips. For comp/none first-active-path: render 4 chips, Payment omitted entirely (T1-AC-3), renumbered 1–4, and append a `Badge variant=secondary` "Payment skipped — {Comp|Free}" after the row. Chips are static (not buttons).
- **Table** `aria-label="Registration paths"` `min-w-[52rem]` in the M1 `rounded-2xl border-border bg-card overflow-hidden` container with `overflow-x-auto`. Toolbar row: count badge `Badge variant=secondary rounded-full tabular-nums aria-live=polite` "{n} paths", right-aligned. Columns: **Registration path** (`font-medium text-foreground`; name verbatim — organizers type the "2." / "2.1" numbering into the name, we never generate it) · **Code** (`font-mono text-xs text-muted-foreground`) · **Audience** (reg-type name, or muted "Any") · **Payment** (plain text Card/Invoice/Comp/None) · **Currency** (mono ISO) · **Active** (Switch, inline toggle per T1-AC-4, `aria-label="Toggle {name} active"`; optimistic + `toast.error` rollback on failure; pending = Switch disabled) · sr-only **Actions**: reorder `ChevronUp`/`ChevronDown` ghost icon buttons (`aria-label="Move {name} up/down"`, disabled at list ends, persists swap then `router.refresh()`) + Pencil/Trash2 ghost icons per M1. Currency column is a deliberate divergence from the prototype (spec T1 divergence note).
- **PathDialog** (clone `registration-type-dialog.tsx` RHF+Zod): Name (`Input`, 1–120, helper "Tip: prefix with the flow number shown to your team — e.g. 2.1 Sponsor — Invoice") · Code (`Input`, uppercased on blur, mono; 409 dup → inline field error "This code is already used by another path.") · Audience (`Select`, first item "Any registration type", then event types) · Payment method (`Select`: Card / Invoice / Comp — free with confirmation / None — free) · Currency (`Select`, ISO list per M2 FeeDialog, default org/event currency) · Sort order (`Input type=text inputMode=numeric`, default prefilled max+1 on create, helper "Lower numbers appear first — you can also reorder from the table.") · Active (`Switch`, default on). Comp/none selection reveals inline `FormDescription`: "The Payment step is skipped for this path."
- **Delete**: reuse `DeleteEntityDialog`. 409 → blocked (Close-only) mode with server message; description suggests "Deactivate instead". Unreferenced → normal confirm.
- **States**: empty = `EntityEmptyState` icon `Compass`, title "No registration paths yet", description "A path is the flow a registrant walks through — one per audience × payment method.", action "+ Create path" (flow card hidden). Error = `EntityTableError entityLabel="registration paths"`. Success/permission/mutation-failure toasts per M2 §5.
- **Responsive**: flow card chips wrap naturally; table scrolls horizontally <768px; header wraps.

## 2. Form builder — Commerce palette (`src/features/form/`)
Extend `form-builder-workspace.tsx`; palette gains a labelled section under the existing three entries: `p className="text-xs font-semibold uppercase tracking-wide text-muted-foreground"` "Commerce", then two entries in the existing palette-card style with `Ticket` and `TicketPercent` icons, each carrying `Badge` "New" (`bg-primary/10 text-primary rounded-full text-[11px]` — the prototype's violet accent mapped to the primary token, no ad-hoc violet).

- **Disabled logic**: entry renders `disabled` (`opacity-50 cursor-not-allowed`, `aria-disabled`) when (a) a field of that type already exists — Tooltip "Only one {ticket selector|promo code} per form" — or (b) template builder context (`form-template-builder-workspace.tsx` simply omits the section; nothing to disable there — cleaner than a disabled entry, matches spec "template editor palette omits them").
- **Canvas row** (`SortableFieldRow`): label + subtitle `font-mono text-xs text-muted-foreground` — ticket-selector: `ticket · from Ticket Types`; promo-code: `promo_code · from Promotions`. Trailing `Badge` "event field" plus the "New"-accent border (`border-primary/40`) while unsaved this session. Draggable/removable like event fields.
- **Settings panel** — ticket-selector: Key row locked `ticket` (mono, LockKeyhole icon), Label (`Input`, default "Select your ticket"), Description/help text (`Textarea`), Required `Switch` (default on). No binding controls — panel footer note `text-xs text-muted-foreground`: "Options come automatically from this event's Ticket Types and Pricing." Promo-code: Key locked `promo_code`, Label (default "Promo code"), Placeholder (`Input`); no Required switch (always optional) — note: "Always optional. Codes are validated at checkout."
- **Builder guards**: zero-TicketTypes warning on save (T2-AC-9) = non-blocking `toast.warning` "Saved. This event has no ticket types yet — add them before publishing registration." Preview pane renders ticket-selector as a disabled radio-card placeholder ("Options appear on the live form") and promo-code as a disabled input + Apply button.
- **Template messaging**: if a template-linked form somehow receives a commerce field via a stale client, server rejection surfaces as the standard save `toast.error` with the server message; no bespoke UI.

## 3. Public multi-step registration — `src/features/public-registration/` (new), route `src/app/events/[eventId]/register/`
Public look inherits `public-event-detail.tsx` tokens: `bg-[#fff8f1]` page, white `rounded-[2rem]` cards, orange accents, slate text. Mobile-first: single column `max-w-2xl mx-auto px-4`; must pass at 375px (T3-AC-13). Light theme only (public surface convention).

- **Path picker** (`PathPickerPage`, ≥2 active paths): heading "How are you registering?" + event name eyebrow. One `Link` card per active path in sortOrder: `rounded-[1.5rem] border border-slate-200 bg-white p-5 hover:border-orange-300 transition` — path name (`text-lg font-semibold`), meta line `text-sm text-slate-600` "{Audience or Anyone} · {Pays by card|Invoiced|Complimentary|Free}", trailing ChevronRight. Whole card is the link (keyboard: one tab stop each). 0 paths → legacy flat form untouched; 1 → server redirect (no picker flash).
- **StepperHeader**: `nav aria-label="Registration steps"` + `ol` horizontal. Per step: numbered circle (`h-8 w-8 rounded-full border text-sm font-semibold`) + label. Current: `bg-orange-600 text-white border-orange-600`, `aria-current="step"`, label `font-semibold text-slate-950`. Completed: `bg-orange-100 text-orange-900` with `Check` icon (`sr-only` "completed"). Upcoming: `border-slate-200 text-slate-400`; connectors = `h-px flex-1 bg-slate-200` (completed segments `bg-orange-300`). Comp/none paths render 4 steps — Payment never appears (spec T3-AC-2 overrides any "grayed" treatment). ≤640px: labels hidden except current step's (`hidden sm:block` + current forced visible); circles always shown. Steps beyond `lastStepReached+1` are non-interactive (circles are not buttons at all in M3 — Back button is the only backward nav; zero tamper surface).
- **Step shell** (`RegistrationStepper`): card contains `h2 tabIndex={-1}` step title; on step change focus moves to it and an `aria-live="polite"` region announces "Step {n} of {total}: {title}". Footer: `Button variant=outline` Back (hidden on step 1) + primary Continue / "Confirm & pay" / "Complete registration"; submitting = both disabled, spinner (`Loader2 animate-spin`) + "Saving…" on the primary. Per-step server errors render an inline `role="alert"` banner (`rounded-2xl border-red-200 bg-red-50 text-red-900 p-4`) above the footer; network failure adds a Retry button in the banner.
- **Step 1 — Personal Information**: reuse `event-registration-form-card.tsx` field rendering (non-commerce fields, existing RHF + `buildFormSubmissionSchema` client validation); Continue POSTs the draft.
- **Step 2 — Ticket & Options** (`TicketOptionsStep`): ticket-selector = `RadioGroup` of radio-cards, one per eligible ticket: `rounded-[1.5rem] border p-4 flex items-start justify-between gap-3`; left: name (`font-semibold`), code (`font-mono text-xs text-slate-500`); right: price (`tabular-nums font-semibold`, "Comp" when 0) — all prices server-provided. Selected: `border-orange-400 ring-2 ring-orange-100`. Sold-out: `RadioGroupItem disabled`, card `opacity-60`, amber `Badge` "Sold out" (visible + disabled semantics — never hidden). Label wraps the whole card so the full card is clickable; arrow keys move selection per Radix RadioGroup. Zero eligible tickets → empty panel "No tickets available for this path" + "Choose a different registration path" link back to picker; Continue disabled. **Registration-type picker** (only when path audience = Any and selected ticket resolves ambiguous per T1 rule): a second labelled `Select` "Register as" appears below the cards with the eligible types; required before Continue; wrapped in a `aria-live=polite` container since it appears/disappears with ticket choice. **Promo code**: labelled `Input` + `Button variant=outline` "Apply" (Enter in the input applies, does not advance the step); pending = button spinner; valid → input swaps to a chip row `Badge` "{CODE} applied — −{amount}" + X button "Remove code"; invalid → inline field error, generic "This code isn't valid." (identical for every failure cause).
- **Step 3 — Registration Summary** (`SummaryStep`): "Your details" block (dl of step-1 answers, `text-sm`, muted dt) with a "Edit" text-button returning to step 1; then quote card: line items `flex justify-between text-sm tabular-nums` — ticket base price, discount row (`text-emerald-700`, "Promo {CODE}" / −amount) when present, one row per tax line, `Separator`, Total `text-base font-semibold`. All amounts arrive formatted-ready from the quote endpoint (minor units + currency → `Intl.NumberFormat`); nothing computed client-side. Quote loading = 4-row `Skeleton` list; quote error = inline retry banner, Continue disabled.
- **Step 4 — Payment**: card paths: simulated form — Name on card, Card number (`inputMode=numeric`, grouped placeholder), Expiry + CVC on one row; persistent `InfoNote`-style banner: "Simulated payment — no real charge is made in this environment." Client validation format-only. `PAYMENT_FAILED` → stay here, banner with provider reason, "Try again" (new attempt key). Invoice paths: no inputs — billing-terms confirmation block ("You'll receive an invoice at {email}. Your place is held once you confirm.") + primary "Confirm registration". Comp/none: step never renders; step 3 primary becomes "Complete registration".
- **Step 5 — Confirmation** (`ConfirmationStep`): centered — emerald check disc, "You're registered!", Registration reference (mono, large) + Order reference/amount/status line, QR placeholder: `h-40 w-40 mx-auto rounded-2xl border-2 border-dashed border-slate-300 grid place-items-center` with `QrCode` icon + caption "Your entry pass" and `text-xs text-slate-500` "Your QR code will appear here and in your confirmation email." Focus lands on the heading; stepper shows all complete; no Back.
- **Typed errors** (mapping per spec, raw codes never shown): `SOLD_OUT`/`TYPE_FULL` → `toast.error` "That ticket just sold out" + jump to step 2 with availability refetched (previously-selected card now disabled/Sold out); `NO_FEE`/`INVALID_REFERENCE` → banner "This selection is no longer available", step 2; `PROMO_EXPIRED`/`PROMO_EXHAUSTED` → step 2, code chip cleared, generic promo error; `PRICE_CHANGED` → auto re-quote, show step 3 with `toast.info` "Prices were updated — please review". 429 → banner "Too many attempts — please wait a moment."
- **Resume**: sessionStorage token found → skeleton card while GET-by-token hydrates, then land on `lastStepReached`; invalid token → silently start fresh.

## 4. Responses workflow — `src/features/responses/` rework
Both surfaces move from the card list to the prototype **table** (workspace: Name · Email · Event · Ticket · Status · Submitted · actions; per-event drops Event). Workspace keeps `DashboardPageHeader`; table in the M1 card container, `min-w-[64rem]`, `overflow-x-auto`.

- **StatusBadge** (shared, `responses/components/status-badge.tsx`): pill with leading dot (`span h-1.5 w-1.5 rounded-full`) + text. Accepted: emerald (`bg-emerald-100 text-emerald-900 dark:bg-emerald-950 dark:text-emerald-200`, dot `bg-emerald-500`); Pending: amber equivalent; New: `Badge variant=secondary` styling, dot `bg-slate-400`; Reviewed: `variant=outline`, dot `bg-sky-500` (`dark:` text kept ≥4.5:1). Dot + text — never color-only.
- **Toolbar**: search `Input` (existing) · event `Select` (workspace only) · status `Select` (Any status / New / Pending / Reviewed / Accepted — drives the Firestore query via URL param `?status=`, not client filtering) · count badge · `Button variant=outline` "Export CSV" (Download icon) right-aligned. Export: anchor-download of the filtered export URL; while preparing, button disabled + spinner; failure `toast.error "Export failed — try again."` Per-event page: same toolbar minus event filter + "Load more" outline button below the table (cursor paging, spinner while loading).
- **Row actions**: `DropdownMenu` (new primitive) on a ghost `MoreHorizontal` icon button `aria-label="Actions for {name}"`. Items = only legal forward transitions from the row's status: "Mark as pending" / "Mark as reviewed" / "Accept" (Accept styled `text-emerald-700` with Check icon). Accepted rows render no menu button — an em-dash — since accepted is terminal in M3. Optimistic badge update + rollback toast on failure; 409 → toast "This response was already updated — refreshing." + refresh.
- **No bulk selection in M3 (decision)**: transitions are forward-only with a per-doc accept side-effect (attendee hook fires once per doc); a bulk action would need partial-failure UI and a bulk endpoint the spec doesn't define, and the prototype shows none. Single-row menus keep each accept auditable. Revisit with M5 attendee lifecycle.
- **Cells**: Ticket = `ticketLabel` or muted "—" (legacy rows); Submitted = existing `getResponseSubmittedLabel`. Row click (excluding the menu) opens the existing event responses link / detail as today.
- **States**: loading = table skeleton (`EntityScreenSkeleton withToolbar`); empty = existing `DashboardEmptyState` (copy unchanged; filtered-empty: "No submissions match these filters" + "Clear filters" button); error = `EntityTableError entityLabel="responses"`; permission 403 on transition/export → toast per M2 §5.
